Вам нужно проанализировать весь трафик, которым обменивается ваш компьютер с адресом 192.168.1.5 и веб-сервером 93.184.216.34 (например, example.com). Какой фильтр вы используете?

a) ip.host == 192.168.1.5 && ip.host == 93.184.216.34</br>
b) ip.addr == 93.184.216.34 && ip.src == 192.168.1.5</br>
c) **ip.addr == 192.168.1.5 and ip.addr == 93.184.216.34**

> ip.addr и ip.host — не просто значения, а множества. ip.addr: {ip.src; ip.dst}. ip.host — псевдоним addr, но он занимается ещё и резолвингом доменных имён. То есть ip.host == "ya.ru" эквивалентно `ip.addr == 5.255.255.242 or ip.addr == 77.88.44.242 or ip.addr == 77.88.55.242`
>
>Следовательно a и c сработают. b получит только те запросы, которые идёт с 192.168.1.5, но не на него.

В дампе трафика присутствует служебный протокол SSH (порт 22), который мешает анализу веб-трафика. Какой фильтр скроет весь SSH-трафик, но покажет все остальное?

 a) **not ssh**</br>
 b) tcp.port != 22</br>
 c) !(tcp.port == 22)</br>
 d) Все варианты верны</br>

> `a) not ssh`
>
>Логично было бы предположить, что 22 порт является зарезервированным под ssh и по нему может прийти только ssh. Однако я, будучи суперпользователем могу спокойно отправить по 22 порту http запрос, а фильтр на порт его не примет. Более того, мне никто не мешает запустить ssh по порту 1234 или 2222. Тогда фильтр не сработает.
>
>Wireshark смотрит протокол не по порту, а по данным (заголовки). Следовательно он сможет его распознать, даже если он не на своём порте.
>
>Если выбирать между != и !(...), в данном случае !() более правильный.
>!= со списочными полями работает так: если один из них не равен, истина. {22,1234} != 22 → истина.
>\=\=: если один из них равен, истина. Следовательно !(...): если один из них равен, истина. !({22, 1234} == 22) → ложь.

Чтобы проанализировать всю сессию (все запросы и ответы) между вашим компьютером и этим сайтом, нужно отфильтровать трафик по номеру TCP-порта источника и назначения. Какой фильтр будет правильным, если IP вашего компьютера — 192.168.1.10, а IP сервера — 10.10.10.10, и вы установили, что связь шла через порт 54321 вашего ПК и порт 80 сервера?

 a) ip.src == 192.168.1.10 and tcp.srcport == 54321 and ip.dst == 10.10.10.10 and tcp.dstport == 80</br>
 b) (ip.src == 192.168.1.10 and tcp.srcport == 54321) or (ip.dst == 10.10.10.10 and tcp.dstport == 80)</br>
 **c) (ip.addr == 192.168.1.10 and tcp.port == 54321) and (ip.addr == 10.10.10.10 and tcp.port == 80)**</br>

> Этот вариант неидеален, но он лучший из предложенных:
> a) Пропустит трафик только в сторону сервера.
> b) Пропустит сильно больше, чем нужно, но только исходящие: запросы на другой сервер, запросы с другого порта.
> с) Пропустит следующие варианты:
> 192.168.1.10:54321 ↔ 10.10.10.10:80 — OK
> 192.168.1.10:80 ↔ 10.10.10.10:54321 — Лишнее
>
>Больше подойдёт следующий вариант:

```wireshark
(ip.src == 192.168.1.10 and tcp.srcport == 54321 and ip.dst == 10.10.10.10 and tcp.dstport == 80) 
or 
(ip.src == 10.10.10.10 and tcp.srcport == 80 and ip.dst == 192.168.1.10 and tcp.dstport == 54321)
```

> Примет только 192.168.1.10:54321 ↔ 10.10.10.10:80
